### Breaking

- `lookupEbBody` returns the EB body in its envelope, in the bytes it arrived in, as `Maybe ByteString`, instead of its decoded tx hashes and sizes.
  Missing bodies are `Nothing` instead of an empty list.

- `batchRetrieveTxs` returns `(offset, bytes)` pairs, in ascending offset order, without the tx hash.
  A tx not written yet reads as zeroes (`unwrittenTx`), also in `lookupEbClosure`, which is `Nothing` only without a body.

- `lookupEbClosure` returns the bytes of the EB's txs in body order, without their hashes.

- LeiosDB no longer tracks whether an EB is complete; the fetch logic knows that.
  `writeEbBody` returns only the offsets its local fills filled, and `writeTxs` returns `()`.
  `CompletedEbs` and the `ebs.missingTxCount` column are gone.
  `scanCompleteEbClosuresNotOlderThanSlot` hashes the txs of each EB against its body instead.

- A local fill lands only if the source's bytes hash to the tx the body lists.

- The LeiosFetch server serves a requested tx it does not hold yet as zeroes, and disconnects a client only for offsets outside the endorser block.

- The LeiosFetch server sends the endorser block bytes it stores without decoding them.
  Its `BlockServed` trace gives the endorser block's size in bytes instead of its number of transactions.

- LeiosDB stores an EB's body in its envelope, in the bytes it arrived in, next to where each tx is in the closure, in `ebBodies`, and its closure as one `ebClosures` row, which tx writes fill in place.
  The `ebTxs` and `ebTxBytes` tables are gone.
  There is no migration: delete existing LeiosDB files.

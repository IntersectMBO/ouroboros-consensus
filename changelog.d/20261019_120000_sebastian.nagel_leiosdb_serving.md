### Breaking

- `lookupEbBody` returns the EB body in its wire encoding, as `Maybe ByteString`, instead of its decoded tx hashes and sizes.
  Missing bodies are `Nothing` instead of an empty list.

- `batchRetrieveTxs` returns `(offset, bytes)` pairs, in ascending offset order, without the tx hash.
  A tx not written yet reads as zeroes, also in `lookupEbClosure`, which is `Nothing` only without a body.

- `lookupEbClosure` returns the bytes of the EB's txs in body order, without their hashes.

- LeiosDB no longer tracks whether an EB is complete; the fetch logic knows that.
  `writeEbBody` and `writeTxs` return `()` instead of `CompletedEbs`, which is gone.
  So are `scanCompleteEbClosuresNotOlderThanSlot` and the `ebs.missingTxCount` column.

- Removed `subscribeEbNotifications` and `LeiosEbNotification`.

- The LeiosFetch server serves a requested tx it does not hold yet as zeroes, and disconnects a client only for offsets outside the endorser block.

- LeiosDB stores an EB's body in its wire encoding, next to where each tx is in the closure, in `ebBodies`, and its closure as one `ebClosures` row, which tx writes fill in place.
  The `ebTxs` and `ebTxBytes` tables are gone.
  There is no migration: delete existing LeiosDB files.

### Breaking

- `lookupEbBody` returns the EB body in the bytes it arrived in, as `Maybe ByteString`, instead of its decoded tx hashes and sizes.
  Missing bodies are `Nothing` instead of an empty list.

- `batchRetrieveTxs` returns `(offset, Maybe bytes)` pairs, in ascending offset order, without the tx hash.
  A tx whose bytes are zeroes, which no valid tx is, counts as not written.

- `lookupEbClosure` returns the bytes of the EB's txs in body order, without their hashes.

- LeiosDB no longer tracks whether an EB is complete, and no longer tells what is written to it; the fetch logic knows that.
  `writeEbBody` and `writeTxs` return `()`.
  `CompletedEbs`, `subscribeEbNotifications`, `LeiosEbNotification` and the `ebs.missingTxCount` column are gone.
  `scanCompleteEbClosuresNotOlderThanSlot` hashes the txs of each EB against its body instead.
  Until LeiosFetch announces its acquisitions, the ChainDB learns of acquired closures only at startup.

- A tx the volatile copy of an EB lacks is read from its immutable copy, if any.

- `Ouroboros.Consensus.Leios.Types` exports `hashLeiosTx`, the hash an endorser block names a transaction by.

- The LeiosFetch server decodes the endorser block from the bytes it stores, rather than building it from its references.
  Its `BlockServed` trace gives the endorser block's size in bytes instead of its number of transactions.

- LeiosDB stores each announced point of an EB as one `ebs` row holding the whole EB: its body in the bytes it arrived in, where each tx is in the closure, and the closure, which tx writes fill in place.
  An EB announced at several points is stored at each.
  The `ebTxs` and `ebTxBytes` tables and the `ebs.status` column are gone.
  There is no migration: delete existing LeiosDB files.

- The LeiosDB garbage collection deletes the rows of the volatile partition by slot, in batches, and keeps no marks on disk.
  After a restart, the next `garbageCollect` collects again.

- `leiosDbPromoteToImmutable` copies the EBs into the immutable partition before it returns, so the ImmutableDB never holds a block whose certified EB is missing there.
  It throws if an EB's txs do not hash to its body, which stops the node.
  The background copier and its `TraceLeiosDbCopyError` trace are gone.

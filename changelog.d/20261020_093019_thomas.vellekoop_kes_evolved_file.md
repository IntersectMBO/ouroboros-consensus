### Non-Breaking

- `PraosCredentialsFile` now also accepts a KES signing key file of the
  period-carrying type `KesSigningKeyWithPeriod_<algorithm>` (whose `cborHex`
  is a two-element CBOR array of the absolute KES period and the raw key), as
  the node persists after evolving the key, and builds the `HotKey` at the
  evolution that period amounts to. For both envelope types the loader checks
  that the key really is at the evolution it is taken to be at, by signing a
  fixed message and verifying it against the certificate's hot key, since a
  sum-composition KES key signs at exactly one evolution. The envelope parser
  moved to `Cardano.Crypto.KES.EnvelopeLocked` in `cardano-crypto-class`;
  `KESEnvelopeError` is re-exported from
  `Ouroboros.Consensus.Protocol.Praos.Common` unchanged.
- `KESFileLoadReason` gains `KESFilePeriodBeforeOCert` (file period, opcert
  start period), `KESFileEvolutionTooHigh` (evolution, maximum number of
  evolutions) and `KESFileStructureMismatch` (claimed evolution, the evolution
  the key actually signs at), and loses `KESFileUnsupportedType`, which was
  only raised for the now accepted type.
- `AgentCrypto` gains the superclass `Signable (KES c) ByteString`, which the
  structural check needs; `StandardCrypto` and `MockCrypto` already satisfy
  it.

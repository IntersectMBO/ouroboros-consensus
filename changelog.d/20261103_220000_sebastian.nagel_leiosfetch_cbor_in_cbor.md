### Breaking

- LeiosFetch sends an endorser block in `MsgLeiosBlock` as its version, `0`, then its bytes CBOR-in-CBOR (`[0, #6.24(bytes .cbor eb_references)]`), so a server sends the bytes it holds without decoding them.
  The codec rejects any other version.

- The node's LeiosFetch protocol is `LeiosFetch LeiosPoint EndorserBlockEnvelope LeiosTx`, and `codecLeiosFetch` is a plain `Codec` instead of an `AnnotatedCodec`.
  `Codecs`' `cLeiosFetchCodec` and `Tracers`' `tLeiosFetchTracer` change type with it.

- The LeiosFetch client hashes an endorser block's bytes before it decodes them, and disconnects a peer whose bytes have the requested hash but do not decode, with `ExnLeiosBlockUndecodable`.

- `decodeEndorserBlock` is replaced by `deserialiseEndorserBlock`, which takes an `EndorserBlockEnvelope` and decodes its bytes at the ledger version of its version (`envelopeLedgerVersion`).
  `decodeEndorserBlockEnvelope` rejects bytes beyond `maxEndorserBlockBytesSize` without decoding them, and `mkEndorserBlockEnvelope` puts an endorser block in an envelope.
  `endorserBlockVersion` is now that envelope version, a `Word`, instead of a ledger version.

### Non-Breaking

- Added `EndorserBlockEnvelope`, `hashEndorserBlockBytes`, `hashEndorserBlockEnvelope`, `envelopeLedgerVersion`, `mkEndorserBlockEnvelope`, `encodeEndorserBlockEnvelope` and `decodeEndorserBlockEnvelope`.

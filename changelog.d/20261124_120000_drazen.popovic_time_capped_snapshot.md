### Breaking

- `getSnapshotFor` is now time-capped: building the snapshot reapplies the
  mempool's transactions against the given ledger state in steps under a time
  limit (a tenth of `mempoolTimeoutCapacity`, floored at 0.1s — also the
  default when no `MempoolTimeoutConfig` is given), and when the time limit
  runs out the snapshot contains only a prefix of the mempool's transactions.
  Each step resolves only the inputs declared by its own transactions, so a
  snapshot that is cut short never pays for LedgerDB reads of transactions it
  did not reach.
- `TraceEventMempool` has a new constructor `TraceGetSnapshotFor`, emitted
  after every snapshot computation. It carries the time limit, the slot the
  snapshot is for, the hash of the ledger state it is taken at, how long it
  took, and — when the snapshot was not served from the cached mempool state —
  the number of reapplication steps performed and whether reapplication
  processed every transaction or hit the time limit. Without the latter, a
  block forged from a time-capped snapshot is indistinguishable from a block
  forged from a small mempool.
- `Ouroboros.Consensus.Mempool.Impl.Common`: `revalidateTxsFor` and
  `revalidateTxsFor'` now take a function to read ledger tables
  (`LedgerTables blk KeysMK -> m (LedgerTables blk ValuesMK)`) instead of a
  `ReadOnlyForker`, so the same revalidation primitive serves both the
  background sync (reading through a forker) and the snapshot path (reading
  through the LedgerDB or the mempool's cached values).
- `Ouroboros.Consensus.Mempool.Impl.Common`: removed `computeSnapshot` and
  `snapshotFromValidTxs`; snapshots are built with `snapshotFromIS`, or with
  the new `snapshotFromTxSeq`, which takes the set of transaction ids as an
  argument (see `isTxIds`) so `snapshotHasTx` stays `O(log n)` without
  rebuilding the set on every snapshot.

### Non-Breaking

- New module `Ouroboros.Consensus.Util.TimeBoundedLoop`: single-threaded
  time-capped iteration (`iterateUntilOrTimeout`, `foldOrTimeout`, and the
  `DoneType` and `StepCount` types that `TraceGetSnapshotFor` reports). The
  timeout is checked between steps and an in-flight step is not cancelled, so
  it is not suitable for defensive timeouts.
- Added `restrictValues'` to `Ouroboros.Consensus.Ledger.Tables.Utils`.
- The `tracing` sublibrary renders the new mempool event under the
  `Mempool.GetSnapshotFor` namespace (Debug), with metrics
  `mempoolGetSnapshotForLastDuration` (gauge, ms),
  `mempoolGetSnapshotForCacheHitCount` (counter),
  `mempoolGetSnapshotForLastStepCount` (gauge),
  `mempoolGetSnapshotForEndReachedCount` (counter) and
  `mempoolGetSnapshotForTimeoutReachedCount` (counter).

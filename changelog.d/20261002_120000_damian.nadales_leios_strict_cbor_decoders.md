### Breaking

- `TxHash` and `EbHash` now hold a `PackedBytes 32` in place of a
  `ByteString`. `ebHashBytes` is no longer a record field. Use
  `txHashBytes` and `ebHashBytes` to get the bytes, and the new
  `txHashFromBytes` and `ebHashFromBytes` to build a hash. Both fail unless
  the input is 32 bytes.

- The `TxHash` and `EbHash` decoders reject any length other than 32 bytes.
  This includes the EB hash in the `EbAnnouncement` of a Praos header. Older
  nodes accept that hash at any length.

- `codecLeiosFetch` and `decodeLeiosFetch` take the largest EB tx count as a
  new first argument. The decoders reject an `MsgLeiosBlockTxs` tx count above
  it, or one that differs from the number of txs that its bitmaps request.
  `decodeBitmaps` stops after the entries that cover that many txs.

- `decodeLeiosEb` rejects an item count that is not between 1 and
  `maxTxsPerEb`.

### Patch

- The LeiosFetch server throws a `LeiosDbException` if the database holds a
  tx hash that is not 32 bytes, or more rows for an EB than `maxTxsPerEb`. A
  database that an older build wrote can hold such data.

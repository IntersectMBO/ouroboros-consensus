### Breaking

- The Dijkstra era now runs the new `Leios` protocol: it is
  `ShelleyBlock (Leios c) DijkstraEra` instead of
  `ShelleyBlock (Praos c) DijkstraEra`. This changes `CardanoShelleyEras`,
  every `*Dijkstra` pattern synonym of `CardanoBlock`, `StandardDijkstraBlock`,
  `DijkstraTxOut` and `DijkstraEbMeasure`. Dijkstra headers are now
  `Cardano.Protocol.Leios.BlockHeader.Header`, and its chain-dependent state is
  `LeiosState`, so the Dijkstra header and chain-dependent state encodings
  change.
- `CardanoHardForkConstraints` now requires `LeiosCrypto c`.
- Removed the `ShelleyCompatible (Praos c) DijkstraEra` instance and the
  `LeiosEraBlockHeader (Praos.Header c) DijkstraEra` instance that adapted the
  Praos header to the Leios interface.
- `HeaderView` in `Ouroboros.Consensus.Protocol.Praos.Views` is now
  `HeaderView' body crypto`, parameterised by the header body the KES
  signature covers. `HeaderView crypto` remains as a type synonym for the
  Praos body, but its data constructor is now `HeaderView'`.
- `validateKESSignature`, `doValidateKESSignature`, `validateVRFSignature` and
  `doValidateVRFSignature` take a `HeaderView' body c`; the KES ones require
  `KES.Signable (KES c) body`.
- Added `blockBodyContainsLeiosCert` to `ShelleyBasedEra` and
  `pHeaderContainsLeiosCert` to `ProtocolHeaderSupportsEnvelope`. Neither has
  a default, so instances must define them; eras and protocols without Leios
  return `False` (`defaultHeaderContainsLeiosCert` does so for protocols).
- `fromShelleyLedgerExamplesPraos` (shelley testlib) is now polymorphic in the
  protocol and takes a function rebuilding the example TPraos header as that
  protocol's header.

### Non-Breaking

- Added `Ouroboros.Consensus.Protocol.Leios`, Praos with the Leios header:
  - `Leios`, its `ConsensusProtocol` instance and `LeiosCrypto`, which is
    `PraosCrypto` plus signing the Leios header body.
  - `LeiosConfig`, which wraps the Praos `ConsensusConfig`.
  - `LeiosState`, which is `PraosState` plus the endorser-block announcement
    (`AnnouncedBy`) of the last applied header, with its CBOR encoding.
  - `LeiosHeaderView`, and `TranslateProto` instances from `Praos` and `TPraos`.
- Exported `praosVerifyHeaderIntegrity`, `reupdatePraosState`,
  `validateKESSignature` and `validateVRFSignature` from
  `Ouroboros.Consensus.Protocol.Praos`, for protocols built on Praos.
- Added `Ouroboros.Consensus.Shelley.Protocol.Leios` (the Shelley protocol
  instances for `Leios`) and `Ouroboros.Consensus.Shelley.Node.Leios`
  (`leiosSharedBlockForging`). Forged Leios headers do not yet announce an
  endorser block or claim a certificate.
- Added `praosEnvelopeCheck` to `Ouroboros.Consensus.Shelley.Protocol.EnvelopeChecks`.
- Added the `Leios` instances for `ShelleyCompatible`, `LedgerSupportsProtocol`,
  `HasPartialConsensusConfig` and `EncodeDisk`/`DecodeDisk LeiosState`.
- `blockMatchesHeader` for Shelley-based blocks now also rejects a block when:
  - its header misreports whether the body carries a Leios certificate, or
  - its body carries both a Leios certificate and transactions.

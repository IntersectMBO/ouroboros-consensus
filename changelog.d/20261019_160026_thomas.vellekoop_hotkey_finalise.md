### Patch

- `finalize` on a `HotKey` created without a key producer (`mkHotKey`,
  `mkHotKeyAtEvolution`; this is the hot key behind file-based credentials) now
  poisons the key, erasing the mlocked signing key deterministically. Previously
  the finaliser was a no-op for such keys and the old key stayed in locked
  memory until the GC ran the allocator's finaliser. A credentials reload (for
  example on SIGHUP) therefore erases the previous key immediately. Hot keys
  with a key producer (KES agent mode) already behaved this way.

### Non-Breaking

- Add the `KESKeyFromTheFuture` constructor to
  `Ouroboros.Consensus.Protocol.Ledger.HotKey.KESEvolutionError`.
  `HotKey.evolve` now returns `UpdateFailed (KESKeyFromTheFuture info period)`
  instead of `Updated` when the requested KES period is below the evolution the
  key is already at. The key is left untouched (not poisoned) and becomes usable
  again once the requested period catches up with it. Previously the hot key
  kept signing with its current, higher evolution, producing blocks that
  verifiers reject. As a consequence, a block producer whose KES agent delivers
  a key evolved ahead of the node's clock, or whose clock stepped backwards
  across a KES period boundary, now stops forging and reports why, instead of
  signing with the wrong evolution. Downstream code that pattern matches on
  `KESEvolutionError` (for example the cardano-node KES tracers) needs a new
  arm.

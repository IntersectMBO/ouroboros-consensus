### Breaking

- The Leios hashes are the ledger's 32-byte hashes: `EndorserBlockHash` and
  `RankingBlockHash` replace `EbHash` and `RbHash`, and `TxHash` is now the
  ledger's transaction hash (full hash, not just body). The decoders refuse a
  hash of any other length.
- `RankingBlockHash` is a newtype whose `SignableRepresentation` is the hash's
  bytes, which votes sign. Use `toRankingBlockHash` to convert a `HeaderHash`.
- `EndorserBlock` is a newtype over the ledger's `EbReferences` and replaces
  `LeiosEb`. Build one with `mkEndorserBlock`; `endorserBlockHash` is the hash
  ranking blocks announce for it.
- Endorser blocks use the ledger's encoding and hash, a non-empty map from
  transaction hash to size. A map that names a transaction twice is refused.
- A received endorser block keeps the bytes it arrived in, so its hash is of
  those bytes. `decodeEndorserBlock` returns a function of them, and
  `codecLeiosFetch` and `cLeiosFetchCodec` are an `AnnotatedCodec`, so `mkApps`
  requires a `Monoid` of the LeiosFetch bytes.
- `decodeEndorserBlock` rejects an endorser block whose bytes exceed
  `maxEndorserBlockBytesSize`, which also bounds its references by
  `maxTxsPerEndorserBlock`, so it no longer counts them.
  `byteLimitsLeiosFetch` bounds a `MsgLeiosBlock` by
  `maxEndorserBlockBytesSize` plus the framing honest peers write around it.
- The endorser block functions drop their `Leios` prefix, eg
  `encodeEndorserBlock`, `endorserBlockReferences` and `referencesCapacity`.
  `leiosEbBodyItems` and `encodeLeiosEbMaxFramingSize` are gone.
- `encodeLeiosEbItemSize` is now `sizeEndorserBlockReference`.
- `leiosEbFromTxBytes` is now `endorserBlockFromTxBytes`, and `hashLeiosEb` is
  `endorserBlockHash`, which returns an `EndorserBlockHash` rather than a
  `SafeHash`.

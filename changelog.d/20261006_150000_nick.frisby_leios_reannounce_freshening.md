### Patch

- Leios: age an endorser block by the youngest slot that announces it.

  An endorser block announced at slot Y, acquired, and then announced again at
  slot Z > Y kept two records disagreeing about its age: the fetch logic's
  `ebState` moved to Z, while the ChainDB's `cdbAcquiredLeiosEbs` stayed at Y
  and was pruned once the immutable tip passed Y. Nothing then re-fetched the
  endorser block, so no closure-completion notification ever restored it, and
  `isUnacquiredCertRB` hid its CertRB from chain selection permanently.

  `writeEbPoint` now repeats, at the new point, whichever notifications the
  endorser block has already earned: `AcquiredEb` once its body is stored and
  `AcquiredEbTxs` once its closure is complete. The announcement path calls it,
  so the acquired-closure set is freshened by the same event that feeds it
  normally, the new point is persisted for the restart re-seed, and the endorser
  block is offered onward under the slot it was just announced at. A point
  inserted for an endorser block still being fetched also joins the set whose
  closure completion is tracked, so it completes alongside the points already
  tracking it.

  `ebs.ebBytesSize` now means: the body's actual size once that point has
  acquired it, and the first size the point was announced at before that. The
  body is the authority on its own size, so a row written by an announcement is
  corrected when the body lands, and an endorser block is never offered at a
  size an announcement merely claimed. Only the acquired rows are read, by
  `sql_lookup_stored_eb_size`.

  Nothing used to read the column at all, so an existing database may hold a row
  whose size is not its endorser block's. This recomputes every acquired row
  from the references the body actually carries:

  ```sql
  UPDATE ebs
  SET ebBytesSize =
    ( SELECT ( CASE WHEN COUNT(*) < 24    THEN 1
                    WHEN COUNT(*) < 256   THEN 2
                    WHEN COUNT(*) < 65536 THEN 3
                    ELSE 5
               END )
           + SUM( 34 + CASE WHEN txBytesSize < 24    THEN 1
                            WHEN txBytesSize < 256   THEN 2
                            WHEN txBytesSize < 65536 THEN 3
                            ELSE 5
                       END )
      FROM ebTxs
      WHERE ebTxs.ebHashBytes = ebs.ebHashBytes
    )
  WHERE missingTxCount IS NOT NULL;
  ```

  An existing database also lacks the index that lookup seeks on, since
  `sql_schema` runs only when a partition is created:

  ```sql
  CREATE INDEX IF NOT EXISTS idx_ebs_acquired
    ON ebs(ebHashBytes) WHERE missingTxCount IS NOT NULL;
  ```

  Run both against the volatile and the immutable partition alike. The `34` is the
  32-byte transaction hash plus its two-byte CBOR length prefix; the `CASE`
  arms are `cborIntBytesSize`. Rows whose body has not been acquired
  (`missingTxCount IS NULL`) keep the size they were announced at, which is what
  the new semantics says they should hold.

### Breaking

- `storeForgedEb` is removed. The node kernel relays the announcement of each
  endorser block it forges, and queues the endorser block, with the header
  announcing it, for a worker thread that hands them to LeiosFetch
  (`onForgedLeiosEb`), so the forge waits on neither LeiosFetch nor the
  LeiosDB. LeiosFetch takes the endorser block in as it would from a peer: it
  writes it, never fetches it, and emits `AcquiredEb` and `AcquiredEbTxs` once
  both writes are durable, so the node offers it.
- The function `forge` calls with a forged endorser block also takes the
  Leios part of the ledger view at the block's slot.

### Non-Breaking

- LeiosFetch's `EbFetchState` has a new state, `ReceivingFromForge`, for a
  point whose endorser block the node's own forge produced and is writing. It
  overrides whatever the point was in (`markReceivingFromForge`), recording
  what of the point's acquisition the node had already emitted
  (`AlreadyEmitted`). LeiosFetch requests nothing at such a point, prunes
  every offer of it, and discards every reply for it, after validating it and
  releasing the request. Only the forge's writes settle it
  (`settleReceivingFromForge`), once both are durable, into `BodyAcquired`
  with no job left, emitting what had not been emitted yet.
- `Ouroboros.Consensus.MiniProtocol.LeiosNotify.Client.Announcements.Validation`
  gains `validHeaderAnnouncement`: the announcement a header carries, once the
  header is known to be valid, as one the node's own forge built is.

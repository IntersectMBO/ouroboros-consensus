### Non-Breaking

- Add the constructor `PraosCredentialsFile` to
  `Ouroboros.Consensus.Protocol.Praos.Common.PraosCredentialsSource`. It
  carries an operational certificate, the path of a KES signing key file (the
  `KesSigningKey_<algorithm>` text envelope that `cardano-cli` writes) and an
  optional, not yet used, `KESPersistHook`. `instantiatePraosCredentials`
  reads such a file straight into mlocked memory, hex-decodes the key in
  place, checks that the derived verification key is the certificate's hot
  key and builds the `HotKey` at evolution 0; no copy of the key ever reaches
  the GHC heap, unlike `PraosCredentialsUnsound`, which stays available
  unchanged. Failures are reported as the new `KESFileLoadError`, whose
  `KESFileLoadReason` and `KESEnvelopeError` carry the path, field names,
  offsets and lengths only, never file contents.
- Add `KESPersistHook` and the method `runKESPersistHook` to
  `Ouroboros.Consensus.Protocol.Praos.AgentClient` and the type
  `KESPersistCallback` to `Ouroboros.Consensus.Protocol.Ledger.HotKey`, in
  preparation for persisting the evolved KES key. Instances of
  `MonadKESAgent` outside this repository need to add the method.

### Breaking

- `LeiosDbWriter.writeTxs` now takes the `LeiosPoint` of the EB.
  The tx bytes are keyed by `TxOffset`, their offset in the EB body, not by `TxHash`.
  The tx is stored if all these conditions are true: the EB body is written, the offset is in the body, the tx is not stored yet, and its size is the declared size.
  Otherwise, the tx is dropped.

- LeiosDB stores tx bytes per EB, in a new `ebTxBytes` table.
  Its key is `(ebHashBytes, txOffset)`.
  The shared `txs` table, keyed by tx hash, is gone.
  When the EB body arrives, LeiosDB allocates the rows. When the txs arrive, it fills them in place.
  Thus writes are sequential, and GC evicts an EB with range deletes.
  The `ebsMissingTxs` and `gcTxCandidates` tables, the `idx_ebTxs_txHashBytes` index and the GC sweep of orphaned txs are gone.
  There is no migration: delete existing LeiosDB files.

- `deleteDanglingTxs` now deletes the tx bytes of EBs that are no longer announced.

### Non-Breaking

- Added `Ouroboros.Consensus.Leios.Types.TxOffset`.

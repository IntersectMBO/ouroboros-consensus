### Breaking

- The `ChainDB` gained `getLeiosValidClaims`, which reads the current ValidClaims value with a fingerprint that changes whenever a claim is added.

- `ValidClaims` now records the endorser block each claim announced, so `insertValidClaim` takes it and `isCertifiedEb` answers whether an endorser block's announcement is certified.

- `leiosFetchLogicIteration` takes a predicate deciding which endorser blocks may be fetched at all. An offer it rejects is skipped rather than dropped, so it is reconsidered when the predicate later admits it.

### Non-Breaking

- The Leios fetch logic now only fetches an endorser block once some verified claim announced it, and the node wakes that logic when a claim arrives after the offer did. This is deliberately stricter than the Recovery Path rule it stands in for --- notably it ignores offers heralded only by LeiosNotify --- and is expected to be weakened.

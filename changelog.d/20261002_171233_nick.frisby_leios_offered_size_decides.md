### Non-Breaking

- An EB announcement's stated size no longer decides anything about fetching.
  `assignBody` requests a body at the size the offering peer named. Previously,
  it passed over any peer whose offer did not match the first size some
  announcement gave for that hash.

  That gate was a too-reliable way to mount threat T22, needing no `L_hdr`
  violation or any honest issuer; just being upstream of enough committee
  members and influential relays. An adversary winning more than one election in
  a window can announce its own endorser block at its true size to just the
  committee members it needs to certify it, and name that same hash at a wrong
  size in its other, contemporary elections. Merely fixing that for the Recovery
  Path wouldn't be enough, since then the EB diffusion would still be idle
  during `L_diff`.

- Only the announcement that takes an election's focus now gives its endorser
  block an `ebState` entry. A second announcement for an already-focused
  election is an equivocation, and tracking its endorser block too let a pool
  double what its won slots cost us. If that one turns out to be the certified
  one, `trackCertifiedEb` gives it an entry then.

- On arrival, a body's hash alone decides whether it is accepted. A peer that
  sent a different number of bytes than it offered still loses the connection,
  now via `ExnLeiosBlockWrongSize` and only after the body has been ingested, so
  it cannot deny us an endorser block by misrepresenting its own offer. The
  LeiosDb records the size the body actually is rather than the size it was
  offered at.

- A `MsgLeiosBlockOffer` claiming zero bytes, or more than `maxLeiosEbBytesSize`
  (the bound the guardrails script imposes), is rejected as
  `ExnLeiosBlockOfferTooBig`, which disconnects the peer. The offered size is
  now what gets requested, so this is what bounds it.

- `LeiosOutstanding` lost `missingEbBodies` and its `reverseSlotIndexByEbHash`
  reverse index. With no size in it, nothing read that structure to decide
  anything: an offer is pursued when some election has the endorser block in
  focus and `ebState` says we do not hold it, and an offer is only accepted from
  a peer that announced that point. It gained `numMissingBodies`, the
  body-fetch backlog maintained as `ebState` changes, which is what the
  `missingBodies` trace now reports.

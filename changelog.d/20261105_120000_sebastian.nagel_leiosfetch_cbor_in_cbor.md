### Breaking

- LeiosFetch sends an endorser block in `MsgLeiosBlock` as its bytes CBOR-in-CBOR (`#6.24(bytes .cbor eb_references)`), so a server sends the bytes the LeiosDB holds without decoding them.
  The bytes carry no version: whoever decodes them knows the era from the announcement.

- The node's LeiosFetch protocol is `LeiosFetch LeiosPoint (Serialised EndorserBlock) LeiosTx`, and `codecLeiosFetch` is a plain `Codec` instead of an `AnnotatedCodec`.
  `Codecs`' `cLeiosFetchCodec` and `Tracers`' `tLeiosFetchTracer` change type with it.

- `decodeEndorserBlock` is gone. `deserialiseEndorserBlock` takes a proxy of the era and a `Serialised EndorserBlock`, and decodes the bytes at the era's ledger version.
  `serialiseEndorserBlock` returns a `Serialised EndorserBlock`.

- `lookupEbBody` returns a `Serialised EndorserBlock`.

### Non-Breaking

- Added `hashSerialisedEndorserBlock`, which hashes an endorser block's bytes without decoding them, and `encodeSerialisedEndorserBlock` and `decodeSerialisedEndorserBlock`, which write and read them CBOR-in-CBOR.
  The decoder rejects bytes beyond `maxEndorserBlockBytesSize` without decoding them.
  `Ouroboros.Consensus.Leios.Types` re-exports `Serialised`.

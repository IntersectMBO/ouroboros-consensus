### Non-Breaking

- An EB announcement arriving over LeiosNotify is now checked against the
  maximum endorser block body size its slot allows. It never was: that check
  lives in `leiosHeaderChecks`, whose only caller is `updateChainDepState`, and
  the announcement path does not go through it --- so an announcement could
  claim any size at all, and only the same header arriving over ChainSync would
  be rejected for it.

  `Ouroboros.Consensus.Protocol.Praos` now exports
  `leiosContextFreeHeaderChecks`, the Leios header checks that read only the
  header and the ledger view, and `validateAnnouncementChainDepState` runs
  them. The one check left behind needs the header's immediate predecessor ---
  a CertRB may not certify an announcement younger than the certification gap,
  and only the predecessor's state says which announcement that is.

  Both paths read the same bound: it is forecast for the header's own slot
  (`maxEndorserBlockReferencesSizeForecastL`), so a forecast either yields the
  view that slot will have or refuses as `OutsideHorizon`.
